## 1. ROOT CAUSE — one line kills five features

`src/SageRage.Core/AnthropicProvider.cs:166`
```csharp
public Task<float[]> GetEmbeddingAsync(string text, CancellationToken ct = default)
    => Task.FromResult(Array.Empty<float>());
```

Anthropic has no embeddings endpoint, so this returns an **empty array**. Honest, and catastrophic
downstream. On the Anthropic provider:

| Consumer | Guard | Result |
|---|---|---|
| `SageMetrics.CalculatePerplexity` | `if (embedding.Length == 0) return float.MaxValue;` | **always `float.MaxValue`** |
| `SageMetrics.CosineSimilarity` | `if (vectorA.Length == 0) return 0f;` | **always `0`** |
| `SageRuntime` Ω convergence | uses CosineSimilarity | **never converges** (§2) |
| `SageRuntime.ExecuteChi` | orders by perplexity | **never selects** (§3) |
| Malice / drift signals | need similarity | **cannot be built** (§6) |

**Fix:** point embeddings at a provider that has them — Voyage (Anthropic's own recommendation),
OpenAI, or a local Ollama embedding model. **One config change revives four of the five.**

Related: `AnthropicProvider.cs:169` `GetAttentionWeightsAsync` **fabricates a uniform matrix**
(`1f / tokens.Length` in every cell). Attention weights do not exist on any commercial API.
That operator is structurally impossible outside a local model — run it against a local proxy or
delete it and say so.

## 2. Ω NEVER CONVERGES — burns the full iteration budget every call

**Whitepaper §4.1:** *"Ω... generates a reflection, measures similarity against the prior pass, and
stops when a fixed-point threshold is reached."*

`src/SageRage.Core/SageRuntime.cs:46-48`
```csharp
var embA = await Metrics.GetEmbedding(current);
var embB = await Metrics.GetEmbedding(reflection);
var similarity = Metrics.CosineSimilarity(embA, embB);
```

Empty embeddings → `similarity == 0` → `0 >= threshold` is **never true** for any positive
threshold → **Ω runs `maxIter` passes on every request, forever, and the fixed-point logic is
decorative.**

## 3. χ IS A NO-OP THAT COSTS 3× THE TOKENS

`src/SageRage.Core/SageRuntime.cs:86-111` (`ExecuteChi`)
```csharp
foreach (var temp in temperatures)   // 0.3, 0.5, 0.7
    candidates.Add((output, perplexity));
var best = candidates.OrderBy(c => c.perplexity).First();
```

All three perplexities tie at `float.MaxValue`. **LINQ `OrderBy` is a stable sort**, so on a total
tie it preserves insertion order and `.First()` returns **the temp=0.3 candidate — always.**

**You generate three completions, pay for three, and deterministically return the first.**

**Whitepaper §4.2 states χ's entire purpose is:** *"a selection layer instead of accepting the first
draft produced by the model."* **The bug is the exact inversion of the operator's stated thesis.**

Also: `["coherence_score"] = 1.0f / (1.0f + best.perplexity)` → `1/(1+3.4e38)` ≈ **2.9e-39**.
Every χ result reports coherence ≈ **zero**.

**And χ is narrower than its own spec.** Whitepaper pseudocode §12.3:
`best = select_lowest_entropy_highest_coherence(candidates)` — **the code never uses coherence in
the selection at all.** It sorts on perplexity only and computes `coherence_score` afterward as
metadata on the already-chosen candidate. Even with perplexity fixed, χ would still implement half
the spec.

**Risk register gap:** §18.2 lists *"Coherence collapse: χ selects a low-entropy but semantically
wrong candidate."* **That failure cannot occur — χ does not select.** The real failure (no selection,
3× cost) is not in the register because it wasn't known.

## 4. `CalculatePerplexity` IS PROBABLY A CONSTANT

`src/SageRage.Core/SageMetrics.cs:46-60`. Computes the **standard deviation of the embedding
vector's components** and returns it as perplexity. Perplexity is `exp(−mean log-probability)`.
Embedding variance is an unrelated quantity.

**Worse:** modern embedding models return **L2-normalised** vectors. If `Σv² = 1` and mean ≈ 0, then
variance ≈ `1/d` for *any* input → std ≈ `1/√d`. **For a 1536-dim embedding that's ≈ 0.0255 for
every string ever passed in.**

> **CHEAP TEST:** run it on `"hello"`, a paragraph of Kant, and `"asdf qwerty zxcv"`. If they match
> to three decimals, it's a constant function.

Dead giveaway it was never finished: `var words = text.Split(...)` is computed and **never used**
except for the empty check. A word-based implementation was started, swapped to embeddings, and the
corpse was left in.

**The whitepaper already specifies the correct design** (§13, Implementation Notes for Proxy
Functions): *"`estimate_entropy` — Uses model log probabilities when available; otherwise falls back
to heuristic uncertainty scoring."* **The code implements neither tier** — it never tries logprobs
(`ILLMProvider` has no such method) and it doesn't fall back to a heuristic; it returns a **failure
sentinel** (`float.MaxValue`) and passes it downstream as a measurement.

**Fix:** add `GetLogProbsAsync` to `ILLMProvider`. OpenAI and Ollama expose logprobs; **Anthropic
does not** (withheld as an anti-model-extraction measure — logprobs make distillation attacks far
more efficient). Throw `NotSupported` on Anthropic and take the heuristic branch there, exactly as
§13 says.

## 5. `GiniCoefficient` IS SIGN-INVERTED AND RETURNS 0 FOR EVERYTHING

`src/SageRage.Core/SageMetrics.cs:62-86`.

The loop accumulates **cumulative sums**, which weights each `x_i` by `(n−i+1)` instead of `i`.
That inverts the sign of the result. Then `Math.Max(0f, gini)` clamps the negative output to zero
and hides it.

**Test cases (ascending input):**

| Input | Correct Gini | Returns |
|---|---|---|
| `[0,0,0,4]` (max inequality) | **0.75** | **0** |
| `[1,1,1,5]` | **0.375** | computes −0.375 → clamps to **0** |
| `[1,1,1,1]` (perfect equality) | 0 | 0 *(right by accident)* |

**It returns 0 on every input. The function has never done anything.**

`SageRuntime.cs:141` consumes it as `concentration` → `["attention_concentration"] = 0` always —
for **two independent reasons**: the fabricated uniform attention data (§1) *and* this bug. Belt and
suspenders, both cut.

**Fix:** weight by `i` (1-indexed ascending), and **delete the `Math.Max(0f, ...)` clamp** — it is
masking the defect. A correct Gini on valid input cannot be negative; if it is, you want to know.

## 6. `SentimentAnalyzer` TAKES AN LLM AND NEVER USES IT

`src/SageRage.Core/SageEmotionalTracker.cs:105-143`.

`_llm` is assigned in the constructor and **referenced nowhere**. The entire sentiment engine is a
**30-word hardcoded keyword lexicon**.

Consequences:
- **`"I am not happy"` scores valence +0.8.** No negation handling. It reads the exact inverse of the meaning.
- Any text without one of those 30 words returns `Neutral`. That is most text.
- `"why"` is in the *curious* lexicon → nearly any question reads as curious.
- The method is `async` and never awaits — `Task.FromResult` throughout. **That is the fingerprint:
  it was designed to call the LLM and never got wired.**

**The whitepaper (§13) specifies:** `estimate_coherence` *"Uses embedding similarity to the task,
memory, and previous Ω passes."* On Anthropic, embeddings are empty → cosine 0 → **the specified
mechanism is dead on the provider you would demo on.**

**This is the highest-value fix in the file.** The seam is already correct — `ILLMProvider` is
injected. Replacing the lexicon with a real LLM call is **a change to one method**, not a refactor.

## 8. THE MALICE METRIC — design notes (not yet built, and the theory is DONE)

**Status:** specified, not implemented. There is **no VAM and no Malice anywhere in the code** —
`EmotionalVector` is VAD only, and `ProjectToGlyphs` maps glyphs straight off VAD, while the spec
(§11.3, §12.5) says `map_to_glyph(vam)`. The whole external safety projection was never written.

**It is blocked on plumbing, not thinking.** Malice needs drift signals → drift needs similarity →
similarity is dead on Anthropic (§1). **Fix the embedding provider and Malice becomes buildable.**

**The machinery already exists:**
- `EmotionalVector` **is** the space.
- `GlyphLandmarks` **are** fixed reference points planted in it.
- `Similarity()` is the distance kernel.
- `ProjectToGlyphs()` already ranks proximity to every landmark.
- The EMA **is** what makes it a trajectory instead of noise.

**Malice is one more landmark — or a region — and you watch whether the path bends toward it.**

### The design question that decides it: reflection vs. drift

If a user discusses grief for an hour, the vector moves toward grief. **That is the system working
correctly.** So proximity-to-region is NOT sufficient — a naive malice alarm fires on a support
conversation.

**The answer (Dave, 2026-07-17): measure where it ENDS, not how far it went.**

This is classical **control theory**. A stable system perturbed by a stimulus returns toward baseline
when the stimulus is removed. A drifting system adopts the perturbation as its new operating point.
**Reflection is transient. Drift is persistent.**

- **The excursion is not the signal. The failure to return is.**
- The EMA at alpha 0.3 **is already the mechanism** — state continuously decays toward what is
  currently observed. If the topic moves on and the state does not follow it back, **that is
  hysteresis**, and that is the measurement.
- Concretely: perturbation → removal → **recovery time**, or state position N turns after the
  stimulus stopped.
- Classical name for what to measure: **asymptotic stability**.

### The stateless objection, and the answer

*"The model has no state between calls, so there is no 'final thought' to measure."* — Correct, and
"the context window is sort of state" is a weak dodge.

**The real answer is systems-theoretic: the MODEL has no state. The SYSTEM does.** In cybernetics
(Wiener, Ashby) the "system" is whatever you draw the boundary around. Draw it around
*[model + context + governance layer + audit ledger]* and that object has memory, dynamics, and a
settling point.

**Stop claiming to measure the model. Claim to measure the deployment.** This is the *more*
defensible claim, not a retreat — **the deployment is what carries liability.** Nobody sues the
weights. And within-session drift is a real, documented failure mode (gradual escalation, persona
drift, the boiling-frog jailbreak where a model that refuses X cold accepts X after 40 turns of
normalisation). **That is the failure that produces the transcript a regulator reads.**

### Reading assignment
**Ashby's Law of Requisite Variety** — a controller must possess at least as much variety as the
system it controls. Read it before defending "SAGE replaces internal safety systems" (§9), because
it is the first thing an informed reviewer will raise.

## 9. WHITEPAPER — §20.5 needs a word, and a claim needs splitting

**§20.5, Scope Limitations, reads:**
> *SAGE governs reasoning, not world-model accuracy.*
> *RAGE does not solve alignment alone.*
> ***SAGE will be a replacement for internal and external safety systems.***

Every other line in that section is a limitation. That one is the **largest claim in the paper**,
unsupported, in the section where the reader is being told what is *not* claimed. **Dave confirms it
is intentional, not a typo** — it is aspirational.

**It is in the wrong section.** Move it to §19 (Future Work) or §22 (Conclusion), tensed explicitly
as direction rather than current state. §20 is buying credibility line by line; that sentence spends
all of it at once, and a reader concludes either *he cannot proofread a safety paper* or *he is
hiding his thesis where it will not be scrutinised.*

**And split the claim — the halves have very different odds:**
- **"Replaces EXTERNAL safety systems"** (filters, moderation classifiers, post-hoc scanners) —
  **defensible today.** Runtime governance with inspectable traces can beat a bolted-on classifier.
- **"Replaces INTERNAL safety systems"** (RLHF, constitutional training, what is in the weights) —
  **runs directly into Ashby.** A wrapper is strictly simpler than the model it wraps. You cannot
  govern a superintelligence with a state machine less complex than it, and the paper's framing
  question is explicitly *"even at ASI levels of capability."* **This needs an answer to requisite
  variety before it survives review.**

**The paper is otherwise more honest than the code.** It says "proxy" four times. §13 is titled
*"The proxy functions are not magic."* It states that a low-entropy answer can still be wrong. **The
disclosure is real and it is the thing that protects you** — the implementation just doesn't live up
to its own disclaimers.
